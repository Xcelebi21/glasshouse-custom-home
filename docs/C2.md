# LG C2 (2022) compatibility

This note describes what the fork changes for an **LG C2 (2022)** and what it does not guarantee. It supplements the [manual guide](MANUAL_GUIDE.md) and [compatibility comparison](REPRODUCIBILITY.md).

## A model name does not identify the webOS version

The C2 family includes OLED42C24LA, OLED48C2*, OLED55C2*, OLED65C2*, OLED77C2* and OLED83C2* models. C2 televisions shipped with **webOS 22** (reported version `7.x`) and may have received **webOS 24** (`9.x`) or **webOS 25** (`10.x`) through an update. Read the version reported by the TV; do not infer it from the retail model name or firmware number.

## What this fork changes

- `server/lib/tv-profile.js` recognizes the C2 and C6 families, maps the reported webOS major version to its marketing name (webOS 22, 24, 25 or 26), and applies the upstream support rules rather than duplicating them.
- `layout.devPorts` replaces the hard-coded filter that kept only HDMI 1 and 3. The shipped default, an empty list, keeps **all** inputs. `[1, 3]` selects ports 1 and 3. Console marks are chosen from the HDMI-CEC device name (Xbox, PlayStation or Switch); unnamed inputs show an HDMI connector glyph. A configured console layout may supply the Switch 2 and Xbox labels for ports 1 and 3, but this is a visual choice, not hardware detection.
- The Bell Fibe tile formerly injected for HDMI 4 and the Bell-specific Applications-row filter were removed; the public build no longer embeds an installation-specific app ID.
- Recommendation support is checked at runtime. If the TV does not expose `applicationmanager/getAllContents`, Home Settings reports that recommendations are unavailable instead of showing an empty row.
- `status()` exposes the detected profile (`model`, `family`, `webos`, `marketing`, `tier`) and `recommendationsAvailable`; a profile is not a hardware test.
- The former Photos tile can be configured as an app shortcut with `layout.shortcutAppId`. It accepts a plain package ID, and the server checks that the app is installed before launching it. The existing `photosAppId` configuration continues to work.

## Support matrix

| Reported version | LG name | Glasshouse Home | Hide LG Home at startup | Notes |
| --- | --- | --- | --- | --- |
| `7.x` | webOS 22 | Experimental | No | Uses the same native Home app ID as webOS 9; rescanning uses the blocked-app list. |
| `9.x` | webOS 24 | Supported by the code | Not enabled in the verified C2 deployment | One OLED55C2PUA running `9.2.2-61` was verified with this fork. This does not certify other C2 sizes, firmware or regions. |
| `10.x` | webOS 25 | Experimental | No | LG Home is a Flutter app under the same ID. Upstream tested it on a G5 (`10.3.1`), not on a C2. |
| `11.x` | webOS 26 | Experimental, behind `allowExperimentalHome` | No | This profile is relevant to the fork's C6 target, not the verified C2. |

“Supported” describes the code's support rules; it is not a guarantee for a particular firmware, region or installed app set. The startup option to hide LG Home is separate from using the Glasshouse Home view and was not enabled on the verified C2.

The verified C2 was later switched to the Glasshouse Home view for a visual review: `home.json` has `enabled: true` and `hideLgHomeAtStart: false`, and the takeover was mounted at runtime only. No boot hook was added, so the server does not start at boot and LG Home comes back after a reboot. `tvwebctl restore-glasshouse-home` puts LG Home back immediately.

## Safe C2 deployment and preview

The recommended source deployment uses the complete `glasshouse/server/` tree. The persistence bundle is also available for compatible existing installations, but its installer requires Node 14.14 or newer on the machine that runs it; it is not needed for a first source deployment.

1. Confirm the TV is already rooted and that an existing maintenance path works. Developer Mode alone is not sufficient.
2. Perform a read-only preflight: record the exact model, webOS and firmware versions, inspect the current Glasshouse configuration and check available storage. Do not change Home, boot behavior or access settings during preflight.
3. Make and verify a private backup of `/var/lib/tvweb/`, including `home.json`, `config.json` and `.previous` if present. Keep it outside Git.
4. Deploy the sources with `deploy.sh --no-persist --no-app`. This updates the server without adding a boot hook or dashboard tile. Do not enable Home takeover or a startup option without separate explicit approval.
5. Verify the server on loopback with token authentication. If an approved developer tile is available, preview the Home view through that tile before considering any Home change.
6. The empty `layout.devPorts` default shows every input. Set it to `[1, 3]` or another list only if that matches the real HDMI wiring.
7. Test navigation, app launch, standby/wake and cold start separately. A software response does not establish panel rendering, remote-key behavior or boot reliability.

## Rollback

- `tvwebctl restore-glasshouse-home` restores LG Home without uninstalling the server; the dashboard's **Use LG Home** option does the same.
- Restore `home.json` from the verified private backup to recover the prior layout.
- If the server does not start, stop its startup hook before restoring files, as described in the manual guide. With a `--no-persist` deployment there is no new startup hook to remove.

## Verification and limits

- **One C2 has been hardware-verified:** OLED55C2PUA, webOS `9.2.2-61 (ombre-okapi)`, firmware `23.25.55`. The profile identified family `c2` and tier `supported`; the server returned HTTP 200 on loopback `127.0.0.1:8080` with token authentication. The developer Home tile launched, and the runtime takeover was later mounted under LG Home's id for a visual review. Startup hiding was never enabled, and nothing is persisted across a reboot.
- Other C2 sizes, firmware versions and regions remain uncertified. The matrix also relies on upstream documentation and offline tests; webOS 22 and 25 remain experimental.
- Recommendations depend on the apps and services. They may be absent or empty even when the API exists.
- No Titan or Lightkeeper compatibility is claimed.
